### 5. Фильтр URL / хостов (P3)

| Поле | Значение |
|------|----------|
| Статус | `нужно решить` |
| Решение | — |

#### Зачем

На CI и в живых базах часто идут «шумные» вызовы, которые не интересны при отладке интеграций: `health`, `ping`, CDN/статика, метрики, проверки лицензии и т.п. Если логирование включено глобально, они засоряют список и раздувают РС.

#### Что должно быть по факту (если делать)

Настройка (список или маски), например:

- не логировать хосты `cdn.example.com`, `*.metrics.local`;
- или URL, содержащие `/health`, `/ping`, `/favicon`.

Перед записью лога в `_ВызватьHTTPМетод` / `ЗаписатьЛог` — проверка: URL подходит под «чёрный список» → **пропустить запись** (сам HTTP-вызов при этом выполняется как обычно).

Альтернатива — «белый список» (логировать только перечисленные хосты). В roadmap фигурировал скорее чёрный список / маски.

**Сейчас:** фильтра нет; пишется всё, что прошло через обёртку при включённом логировании.

### 6. Экспорт HAR / `.http` (P7)

| Поле | Значение |
|------|----------|
| Статус | `нужно решить` |
| Решение | — |

#### Зачем / контекст

Сейчас один лог (или набор) можно сохранить в **свой markdown**-протокол OneSniffer и как **curl** / код 1С. Это удобно внутри продукта, но:

- **HAR** (HTTP Archive, JSON) — формат Chrome DevTools / Fiddler / Charles: можно открыть лог во внешнем инструменте, сравнить тайминги, переслать коллеге без 1С.
- **`.http`** — формат VS Code / JetBrains REST Client: файл с запросами, который открывается в IDE и гоняется оттуда.

#### Что должно быть по факту (если делать)

Новая команда на форме списка (рядом с «Сохранить в файл» / curl), например:

- «Экспорт в HAR» → файл `.har` по выделенным строкам;
- и/или «Экспорт в .http» → файл с METHOD URL + заголовки + тело.

Импорт HAR обратно в РС **не обязателен** для первой версии — речь про экспорт «наружу».

**Сейчас:** только markdown OneSniffer + curl + код 1С. HAR / `.http` нет.
